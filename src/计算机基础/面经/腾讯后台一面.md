## golang

### 两个接口如何比较（判等）

**动态类型**（Type）和**动态值**（Value）均相等

**1).动态类型（Type）必须完全一致**
  例如，`int` 和 `int64` 即使值相同也会判不等。

**2).动态值（Value）的比较遵循具体类型的规则**
  若动态值是基本类型（如 `int`、`string`），直接比较值；若是指针、`channel` 等引用类型，比较的是内存地址；若动态值本身不可比较（如 `slice`、`map`），判等操作会直接报错。

### Context是啥，存储了哪些信息

**`context.Context`** 是一个标准库接口，用于在并发编程中：

**1). 管理协程（goroutine）的生命周期**

 `WithCancel` 、 `WithTimeout` 或 `WithDeadline` 

**2). 传递请求范围的元数据**

通过 `WithValue` 存储与请求相关的键值对（如请求 ID、认证令牌），在协程间共享数据

**3). 协调并发操作**

**适用场景**：

1. **HTTP请求超时控制**

```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

req, _ := http.NewRequestWithContext(ctx, "GET", "https://example.com", nil)
resp, err := http.DefaultClient.Do(req) // 超时自动取消
```

2. **传递请求元数据**

```go
type traceIDKey struct{}
ctx := context.WithValue(context.Background(), traceIDKey{}, "abc123")
traceID := ctx.Value(traceIDKey{}).(string)
```

3. **取消协程链**

```go
ctx, cancel := context.WithCancel(context.Background())
go func() {
    <-ctx.Done()  // 监听取消信号
    fmt.Println("协程终止")
}()
cancel() // 触发取消
```

### RPC都有啥信息

**RPC（Remote Procedure Call）** 是远程过程调用的缩写，是一种允许程序通过网络调用另一台计算机上的函数或方法的技术，开发者无需关心底层网络细节，就像调用本地函数一样

#### RPC包含信息

1.服务名和方法名

2.请求参数-输入参数

3.响应结果-返回值或错误信息

4.元数据-附加信息

请求 ID、超时时间、认证令牌等，用于链路追踪、限流等场景。例如 gRPC 支持通过 `metadata` 包传递键值对。

5.控制信息

a.超时与取消，通过上下文（`context.Context`）传递超时、取消信号，避免长时间阻塞。

b.压缩标识，标记数据是否压缩（gzip）

#### **RPC 通信流程**

1. **客户端**
   - 序列化请求参数。
   - 通过传输协议（如 TCP）发送到服务端。
2. **服务端**
   - 反序列化请求，定位方法。
   - 执行方法逻辑，序列化结果并返回。
3. **客户端**
   - 接收响应，反序列化结果。

### channel有了解吗，讲一下

**Channel（通道）** 是用于协程（goroutine）间通信的核心机制

#### **发送方关闭 Channel 后，接收方能否继续接收？**

接收方仍能继续读取 Channel 中已缓存的未处理数据，直到 Channel 的缓冲区为空。

1. 阻塞式接收（如`v := <-ch`）：
若 Channel 已关闭且无数据，接收操作会立即返回零值，同时第二个返回值`false`，表示 Channel 已关闭。
```go
v, ok := <-ch
if !ok {
    fmt.Println("Channel 已关闭")
}
```
2. **非阻塞式接收**（如 `select`）：
    若 Channel 已关闭且无数据，`case v := <-ch` 会直接执行，`v` 为零值，`ok` 为 `false`。
3. **`range` 循环接收**：
   若 Channel 被关闭，`for v := range ch` **会自动退出循环**，无需额外检查。

#### **接收方关闭 Channel 后，发送方能否继续发送？**

如果接收方主动关闭 Channel，发送方继续向该 Channel 发送数据会**立即触发 panic**

**发送方处于什么状态？**

发送方的行为取决于其发送操作的方式：

- **阻塞式发送**（如 `ch <- data`）：
  若 Channel 已被接收方关闭，发送操作会直接触发 `panic`。
- **非阻塞式发送**（如 `select`）：
  若发送方通过 `select` 尝试向已关闭的 Channel 发送数据，对应的 `case` 分支会直接被跳过（不会触发 panic），发送方需通过其他逻辑处理关闭状态。

### 闭包

### for循环打印1-10,用不同goroutine结果会是啥样

**输出顺序是乱序的**，因为 goroutine 的执行顺序由调度器决定，无法保证同步。

#### **1. 直接启动多个 goroutine**

```go
func main() {
    for i := 1; i <= 10; i++ {
        go func() {
            fmt.Println(i) // 闭包捕获循环变量 i
        }()
    }
    time.Sleep(time.Second)
}
```

可能打印重复值（如多个 `10`）或乱序数字（如 `2, 5, 10, 3...`），原因是:

- **闭包**直接引用外层循环变量 `i`，**所有 goroutine 共享同一个变量**，当它们执行时 `i` 可能已递增到最终值。
- Goroutine **启动和调度存在延迟**，导致打印顺序不可控.

#### **2. 将循环变量作为参数传递**

```go
func main() {
    for i := 1; i <= 10; i++ {
        go func(v int) {
            fmt.Println(v) // 正确传递值
        }(i)
    }
    time.Sleep(time.Second)
}
```

**消除了闭包！**没重复数字，数值 1-10 会被打印，但**顺序完全随机**（如 `3, 1, 7, 2...`），因为多个 goroutine 并发执行，没有同步机制。

#### **3.使用 Channel 控制执行顺序**

通过全局变量 `tag` 和 Channel 协调 goroutine 的执行顺序.

```go
func orderedPrint() {
    ch := make(chan int)
    tag := 1 // 全局变量控制顺序

    for i := 1; i <= 10; i++ {
        go func(v int) {
            for {
                if tag == v { // 循环检查是否轮到当前值
                    ch <- v
                    break
                }
            }
        }(i)
    }

    for i := 0; i < 10; i++ {
        fmt.Println(<-ch)
        tag++ // 触发下一个值
    }
}
```

#### **4.使用两个 Channel 交替打印（奇偶数）**

通过两个 Channel 实现两个 goroutine 交替打印。

```go
func alternatePrint() {
    chA, chB := make(chan struct{}), make(chan struct{})
    wg := sync.WaitGroup{}
    wg.Add(10)

    // 打印奇数
    go func() {
        for i := 1; i <= 10; i += 2 {
            <-chA
            fmt.Println(i)
            chB <- struct{}{}
        }
    }()

    // 打印偶数
    go func() {
        for i := 2; i <= 10; i += 2 {
            <-chB
            fmt.Println(i)
            wg.Done()
            chA <- struct{}{}
        }
    }()

    chA <- struct{}{} // 触发启动
    wg.Wait()
}
```
