## 1. 多源数据爬取：工厂模式与策略模式结合
技术实现：
- 工厂模式：（**动态创建不同数据源的爬虫实例**）创建统一爬虫接口，针对CTI、ATT&CK等不同数据源实现具体爬虫类（如CTICrawler、ATTACKCrawler）。通过工厂类（CrawlerFactory）根据配置动态实例化对应爬虫，屏蔽底层差异。例如：
```python
class CrawlerFactory:
    def create_crawler(self, source_type):
        if source_type == "CTI":
            return CTICrawler()
        elif source_type == "ATT&CK":
            return ATTACKCrawler()
        # 其他数据源...
```
- 策略模式：（**封装不同网站的解析逻辑**）针对不同数据源的解析逻辑（HTML/JSON/API），定义ParsingStrategy接口，实现HTMLParser、JSONAPIParser等策略类。爬虫运行时通过set_parser()动态切换解析策略，例如MITRE ATT&CK的STIX/JSON数据采用专用解析器。

效果：**新增数据源仅需扩展工厂和策略类，无需修改核心架构，配置灵活度**提升90%。

## 2. 增量更新策略：去重+时序+内容过滤
技术实现：
- BloomFilter去重：为每个数据源维护布隆过滤器，存储已采集数据的唯一ID（如CVE编号）。新数据到达时，先检查bf.might_contain(id)，若不存在则放行。采用Guava库实现，设定误判率<0.1%。

  Scrapy的RFPDupeFilter基于请求指纹实现过滤 **sha1(method + url + body + header)**

  继承BaseDupeFilter根据CVE ID等实现自定义布隆过滤器去重


- 时间窗口过滤：针对时序数据（如DFEND日志），在数据源配置中定义retention_days=30，SQL查询时添加WHERE timestamp >= NOW() - INTERVAL '30 days'，过滤过期数据。
- 余弦相似度比对：对文本内容（如Engage威胁描述），使用TF-IDF向量化后计算相似度。设定阈值0.9，低于则视为新内容。采用MinHash优化计算效率，Jaccard相似度替代余弦降低复杂度。
```python
from sklearn.feature_extraction.text import TfidfVectorizer
vectorizer = TfidfVectorizer()
new_vector = vectorizer.fit_transform([new_text])
existing_vectors = load_existing_vectors()  # 预加载存量数据
similarity = cosine_similarity(new_vector, existing_vectors)
if similarity.max() < 0.9:
    store_new_data()
```
效果：通过三级过滤，减少65%的冗余数据处理，每日增量更新耗时从120分钟降至42分钟。

## 3. 数据格式化存储：模式校验与批量导入

```python
from jsonschema import validate
schema = {
    "type": "object",
    "properties": {
        "id": {"type": "string", "pattern": "^T\\d{4}$"},
        "name": {"type": "string", "minLength": 5},
        # 其他字段...
    },
    "required": ["id", "name"]
}
validate(instance=data, schema=schema)  # 抛出ValidationError异常
```
- 外观模式封装：创建DataConverter外观类，提供convert_to_graph(node_data)统一接口，内部调用CTIConverter、ATTACKConverter等模块处理异构数据到图节点的映射。
- **使用MERGE替换CREATE，并对不同节点类型建立索引，关闭事务自动提交，每1万条手动提交一次。**

## 4. 数据查询优化：索引+缓存+预处理
技术实现：

- 索引优化：

**单属性索引**：按CVE/NVD编号查找漏洞

**复合索引**：查找某IP的所有关联漏洞

- Redis缓存：使用Hash结构存储热点节点信息，**键为entity:{type}:{id}，值为序列化JSON**。设置最大内存2GB，启用allkeys-lru淘汰策略，TTL=1小时防止冷数据堆积。

```python
import redis
r = redis.Redis()
cache_key = f"entity:{node_type}:{node_id}"
if r.exists(cache_key):
    return json.loads(r.get(cache_key))
else:
    data = neo4j_query("MATCH (n) WHERE ...")
    r.setex(cache_key, ttl=3600, value=json.dumps(data))
```
- 查询预处理：解析Cypher语句，优先提取固定条件（如n.type='Malware'）利用索引；对多跳查询MATCH (a)-[*3]-(b)，预先计算路径模式并缓存中间结果。

  解析Cypher语句，在Match时加入使用索引，并优先前置索引判断（如n.type='Malware'）

  多跳查询MATCH时，预先计算路径模式，使用Redis缓存中间结果，并将查询结果缓存。

  效果：热点查询响应时间从4.2秒降至0.3秒，复杂关联分析性能提升14倍。

1.数据采集与准备

2.构建数据模型

将所有用户的操作记录进行分组，每个用户会对应一个偏好数组（PreferenceArray）

3. 计算用户相似度

对每一对用户偏好向量计算余弦相似度。

4. 选择最近邻用户

根据计算得到的相似度，为目标用户选择相似度最高的若干个邻居（代码中设置选取最相似的 2 个用户）。

邻近用户集合决定了后续推荐时参考的数据范围，通常是目标用户没有操作过的新闻候选集在这些邻居中进行评分预测。

预测评分与生成推荐
